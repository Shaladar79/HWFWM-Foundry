# P3 First Edition Audit — 2026-10-11

## Scope
Reviewed Skill Talents, saves, prerequisites, specialization and Talent XP purchases, Essence ability blueprints, resources, initiative, player requests, and tactical panel.

## Verified by inspection and automated tests
- Exactly 26 Skill Talents (Power 7, Speed 5, Spirit 11, Recovery 3); five distinct free selections, Magic Theory -> Ritual Knowledge prerequisite.
- Four saves, based on attribute TN. Both extra Skill Talent and specialization purchase prices remain GM-disabled until configured.
- Blueprint preserves Essence, Awakening Stone, optional multi-component fields and unset AP costs.
- Tactical initiative and Action Score are one score: d20 first round; next actor has highest remaining eligible score; actions deduct costs; passes bank points; new rounds add d20 to carried score, including negatives, without a cap.
- GM approves player requests, revalidates current turn revisions and ownership, and derives costs from the actual ability record.
- Approved request IDs prevent ordinary sequential replay. New UI identifies stale requests and allows GM dismissal.

## Known deficiencies / unresolved rules
- HIGH: There is no cross-GM distributed lock or compare-and-swap on Foundry Combat flags. Simultaneous approvals from different GM clients can still race. Recommend one active GM authority until tested and resolved.
- HIGH: Resource mutations and Combat flag updates are separate operations; rollback is compensating, not transactional. If reconciliation fails, manual GM intervention is needed.
- MEDIUM: Foundry's native round/turn tracker is not synchronized to our tactical round/turn state. Modules relying on native turn hooks may not see custom combat progression.
- MEDIUM: When score is positive but below every affordable action cost, the combatant has to pass manually. No automatic affordability-aware skipping is implemented.
- MEDIUM: Tie-breaking currently uses combatant list order; no explicit First Edition tie rule approved.
- MEDIUM: Source ability effects are intentionally not automated; ritual constraints are only enforced for explicitly classified summon/familiar abilities.
- MEDIUM: Character creation and Talent XP transactions use local guards; cross-client concurrency and some partial failures remain possible.
- LIVE TEST REQUIRED: Verify rendering, ownership behavior, chat author identity, multiple players, GM approval, reconnection, token duplicates and Foundry v13 compatibility in an actual session.

## Audit fix applied
GM queue now classifies stale requests, hides approval for them, and provides dismissal. The underlying authoritative validation remains in place.

## Release decision
P3 is an automated-test-backed development build, not a live-multiplayer-certified milestone.
